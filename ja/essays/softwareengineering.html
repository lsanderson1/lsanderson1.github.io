ソフトウェア工学の学びを振り返る

Web 開発を通じて学んだ基礎

ソフトウェア工学の授業では、Web アプリケーションの開発と設計に取り組みました。しかし、学んだことは特定の技術構成で Web サイトをつくる方法だけではありません。制作を通じて、幅広い開発に共通する基礎を学ぶことができました。

特に印象に残ったのは、開発環境、デザインパターン、アジャイルなプロジェクト管理の三つです。それぞれを振り返りながら、Web 開発の外でもどのように応用できるかを考えます。

開発環境：IntelliJ が支える作業

開発環境は、コードの作成、修正、テスト、公開までを支える道具の集合です。エディターの構文強調や補完、デバッガーに加え、バージョン管理、ビルド、テスト、コード内の移動、品質の解析、データベース操作などが含まれます。これらがまとまっていると、作業を切り替える負担が軽くなり、開発に集中しやすくなります。

授業では JetBrains の IntelliJ IDEA を使用しました。Java をはじめ複数の言語を扱え、コードの補完や解析、修正案の提示が助けになりました。変数名の変更やメソッドの抽出といったリファクタリング機能も、変更を整理して行うための道具です。

私の環境では、内蔵ターミナルから PowerShell を使用でき、外部のウィンドウへ移動せずにコマンドを実行できました。授業では多用しなかったものの、ブレークポイント、変数の確認、ステップ実行などのデバッグ機能も用意されています。プラグインで拡張できる点も含め、必要な道具を一つの場所にまとめられることに価値を感じました。

デザインパターン：共通する課題への手がかり

デザインパターンは、繰り返し現れる設計の問題に対する、再利用可能な考え方です。アーキテクチャ、オブジェクト間の連携、データへのアクセスなどを考える際に、実績のある方法を出発点にできます。

たとえば Observer は、あるオブジェクトの変化を、登録された別のオブジェクトへ通知する仕組みです。株価を表示するアプリケーションで、元の価格情報が変わると、グラフやチャートが更新される場面を想像するとわかりやすくなります。同じ変更を複数の表示へ伝える構成を整理できます。

Singleton は、一つのインスタンスと、そこへアクセスする共通の窓口を用意するパターンです。Java の典型的な例では、非公開の静的インスタンスと getInstance() のような公開された静的メソッドを使い、必要な場合にインスタンスを生成します。

ログ管理、キャッシュ、接続管理など、システム内で共有する役割を考える際の例として学びました。設計の型を知っておくことで、問題ごとに一から考える負担を減らし、どの方法が適しているかを検討しやすくなります。

アジャイルなプロジェクト管理

授業では、短い反復、継続的なフィードバック、変更への対応を重視するアジャイルな進め方も学びました。その中で扱ったのが、課題を単位として作業を進める Issue Driven Project Management（IDPM）です。取り組むべき課題を明確にし、優先順位をつけ、解決と振り返りを重ねて目標へ近づきます。

教育用のモバイルアプリケーションをつくる場合なら、UI、教材との連携、技術的な実現可能性などを課題として整理できます。短いスプリントで重要なものから取り組み、利用者の意見を受けて次の作業を調整することで、予想外の問題にも対応しやすくなります。

この考え方は、ソフトウェア以外にも応用できると思います。大規模な地域イベントを計画するなら、会場の確保、食事の手配、ボランティアの募集などを課題として管理できます。定期的に進捗を確認し、優先順位を見直せば、限られた時間や人員を配分しやすくなるでしょう。

おわりに

Web アプリケーションは、授業で学んだことを試す具体的な場でした。その制作を通じて、環境を整えること、設計の考え方を共有すること、課題を整理して協力することの重要性が見えてきました。

開発環境、デザインパターン、アジャイルな管理は、特定のフレームワークや分野だけに閉じた知識ではありません。今回得た理解を土台として、これから出会うさまざまな開発の課題にも応用していきたいと思います。
