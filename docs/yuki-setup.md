## Reduced repetition — local, not yet published

The AI now receives a bounded continuity record: counts of the canonical story topics it has actually discussed and the last four reply openings. Variety guidance is deliberately lenient: familiar phrases, recurring motifs, recaps and returning to a favorite story are welcome when relevant. It does not demand a new fact or anecdote in every answer or mechanically rotate stories. It discourages substantial whole-answer loops, while retaining the separate no-repeated-introductions rule. The model tags each answer with at most three allowlisted story IDs; project-only answers should return none. Story facts and documented project facts take priority over novel wording. The request adds no paid provider, embeddings service or permanent memory.

The same tab session keeps at most twelve recent assistant-reply similarity fingerprints and 64-character openings, plus capped canonical topic counts. Fingerprints are compact text-similarity data, not encryption or anonymization. Only this bounded metadata and the existing recent chat are sent on the next explicit Send; nothing is sent on scrolling or idle. Metadata follows the existing session lifetime, page/language continuity and Clear chat behavior. The privacy disclosure explains it. UTF-8 request packing retains the existing 14 KB ceiling, trimming older metadata/history when needed for long Japanese messages rather than rejecting an otherwise valid message.

A deterministic English/Japanese near-copy check compares a valid model answer with recent replies before displaying it. Its similarity threshold is deliberately high (0.92 rather than the initial 0.78; a heuristic score, not a percentage guarantee) so familiar explanations normally need only one inference. If it scores as almost verbatim, there is enough time, and the visitor did not explicitly request repetition, the Worker may ask the same AI for **one wording revision**. This is a second inference with a separate atomic reservation against the same global, visitor and minute limits. Each inference retains the fixed model and 700-token cap. It can use free allowance faster; it does not add a paid fallback or raise any limit. Failed initial provider requests are not retried. The optional revision has a maximum 12-second wait and a 38-second request-time budget; slow first answers skip it. Cancellation is checked before starting it.

The revised answer must score better and retain the original navigation destination, source links, emotion and gesture. If quota is exhausted, the revision fails, it still repeats, or those fields change, return the original valid answer rather than loop or fabricate a replacement. Short necessary facts and explicitly requested quotations/repeats are exempt. Wording similarity is a heuristic, not full semantic equivalence: it cannot guarantee zero repetition or that an AI paraphrase preserves every factual nuance. Live English/Japanese long-conversation review remains necessary after website and Worker publication.

## Initial safeguards (unchanged limits)

- At most **100 reserved model requests per UTC day**, **20 per visitor/IP per day**, and **4 per minute per visitor/IP**. Reservations are atomic; failed provider calls still use a reservation. Visitors sharing a network share that visitor limit.
- Each inference has a maximum of 700 generated tokens and bounded input. Failed requests are not automatically retried. An optional near-copy wording revision is independently reserved as a second inference, at most once per Send, as described above. A 22-second initial inference timeout bounds the wait but cannot cancel work already running at Cloudflare. These application limits reduce usage; the **Cloudflare Free plan**, not a dollar cap in our code, prevents paid overages.
- A missing binding/secret, unconfirmed free plan, bot verification failure, exhausted limit, missing quota service or unavailable site index results in a clear unavailable response. The guide buttons and animations remain usable; no canned message is passed off as an AI answer, and no paid or unprotected fallback is called.
- `CHAT_ENABLED = "false"` + redeploy immediately stops new model calls. `_data/yuki.json` `enabled:false` hides the companion on the next site publish.
- Model output is plain text plus allowlisted emotion/gesture choices. Links come from the server's site index, not arbitrary model URLs. Suggested navigation needs the visitor's click.
- Messages and recent conversation go to Cloudflare Workers AI only when the visitor consents and sends; consent also loads Cloudflare's Turnstile check. We do not store chat transcripts server-side. The browser keeps the latest 12 messages in tab session storage, expires them on reload after 30 minutes, and offers Clear chat. Quota storage contains daily salted IP hashes/counters and expires after two days. Cloudflare's [data usage policy](https://developers.cloudflare.com/workers-ai/platform/data-usage/) and applicable model terms still apply. Revoking consent cancels the browser's pending request/display, not data already sent.
- This first integration is **text chat**, not microphone input, voice synthesis or word-synchronized lip-sync. Approved talk/reaction animations express the response; voice can be added separately later.
